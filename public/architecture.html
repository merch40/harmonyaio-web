The permission model

Confidence is not
authorization.

Permission is a deliberate boundary. The policy for the environment determines which capabilities can run and which require a decision.

Yes

Allowed by policy.

A permitted capability can proceed after validation, within its defined scope.

Example policy: read a service’s status.
Ask

Wait for a decision.

Review the proposed action before it runs. Approve it or decline it.

Example policy: restart a production service.
No

Stop at the boundary.

A blocked capability does not become allowed because the model recommends it.

Example policy: disallow a destructive action.

A few useful distinctions

Understand the
boundaries.

Does Harmony act without asking?

That depends on the capability and the environment’s policy. The architecture distinguishes allowed actions, actions requiring review, and blocked actions. Early access behavior and specific automation coverage should be confirmed for the intended workflow.

Do the current videos show a live repair?

The current recordings demonstrate the workspace and a review-and-denial flow using fictional data and scripted responses. They do not show a successful endpoint repair. Each demonstration includes its scope and limitations.

Can I use my existing AI subscription?

Harmony needs a supported integration or model API configuration. Access to a consumer chat application does not necessarily provide the API credentials or entitlement required.

Where should I start?

Watch the product demonstrations, read the founder story, and join the early access list. The videos show the current interface and the decisions an operator makes in it.
